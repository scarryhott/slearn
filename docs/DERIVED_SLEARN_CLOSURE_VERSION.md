# Derived Slearn closure version

This is the source-grounded Slearn version model. It joins two existing
contracts instead of creating another independent closure theory:

- `PerspectivalCurvatureClosurePrimitives.lean` supplies the Slearn relation
  `perspective ↔ belief/value limit ↔ WHY ↔ goal`, the paired
  explanation/definition presentations, a counter-path, review, and a
  nonterminal return.
- `AuditableChangingAxiometryProtocol.lean` supplies the bounded method-level
  audit: relation-relative axiom/geometry closure, retained residue, a changed
  derived axiometry/verifier, and a held-out relation.

[`DerivedSlearnClosureVersion.lean`](../Slearn/DerivedSlearnClosureVersion.lean)
requires them to describe the **same** perspective/goal translation. A
closure version therefore cannot be an arbitrary interface or a completion
badge. It has the following dependency:

```text
source curvature packet
  → reviewed interaction + changed returned perspective
  → same P ↔ G translation closes in the audit witness language
  → receipt is linked to the audit return evidence
  → residue derives a changed axiometry and verifier
  → next relation is the audit's held-out relation
  → next Slearn version recentres on the returned perspective
```

## What the module checks

For one `ClosureVersion`, Lean proves that:

- its source perspective and goal close only through the admitted witness
  relation, not literal endpoint identity;
- the successor perspective differs from the source perspective;
- the audit's return evidence is explicitly tied to the Slearn receipt;
- the next relation is the audit’s held-out relation;
- the predecessor verifier cannot evaluate that relation, while the derived
  verifier has the declared verdict;
- the derived verifier and axiometry are each non-frozen in the supplied audit
  model; and
- the Slearn project, returned experience, and OPEN remainder are generated
  from the same returned packet. No authored graph or UI input is present.

A `Succession first second` requires the second curvature packet to recenter
on the first returned perspective; its old verifier to be the first derived
verifier; its current frame to be the first derived axiometry frame; and the
first further relation to re-enter as the second packet's observed material.
The inherited verifier evaluates that re-entered material. The successor's
**own distinct held-out relation** remains unevaluable by its current verifier,
so it is the new opening rather than a silent self-certification.

The module also contains a small two-version Boolean/`Unit` consistency model.
It proves that this timing is inhabitable: the first return's `false` relation
is re-entered and evaluated as the second version's observation, while the
second version's distinct `true` relation remains OPEN to its current verifier.
The values are formal tokens, not a learner, evidence source, or educational
measurement.

## Scope boundary

The source and audit records carry attempts, reviews, independence claims, and
external evidence as supplied data. Lean checks that the data are linked in the
required order; it does **not** turn a token into an independent human review,
prove an external result, establish educational benefit, or show that all
languages/axiometries are comparable. The existing experiment record remains
`DESIGN_READY`, not an executed closure version.
